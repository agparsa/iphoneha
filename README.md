# آیفونی‌ها — فروشگاه تخصصی آیفون

فروشگاه اینترنتی کامل برای فروش گوشی‌های آیفون: فروشگاه موبایل‌فرست فارسی (RTL)، ورود فقط با شماره موبایل و کد یک‌بارمصرف، سبد خرید و تسویه هفت‌مرحله‌ای، پرداخت نقدی، خرید اقساطی با چک صیادی و سفته (صفحهٔ هر روش، محاسبه‌گر و فرم درخواست) و آمادگی برای شش سرویس اعتباری، مجلهٔ راهنمای خرید، مدیریت موجودی با رزرو اتمیک (بدون فروش بیش از موجودی) و پنل مدیریت کامل.

|         |                                                                               |
| ------- | ----------------------------------------------------------------------------- |
| فروشگاه | Next.js 16 (App Router) + Tailwind CSS 4 + TanStack Query                     |
| API     | NestJS 11 + Prisma 6 + PostgreSQL 16 + Redis 7 + BullMQ                       |
| مشترک   | پکیج `@iphoneha/shared` (Zod، انواع، توابع مالی و برچسب‌ها)                   |
| تست     | Jest (واحد + یکپارچه) و Playwright (E2E + دسترس‌پذیری، سئو و امنیت) — ۵۲۹ تست |

## شروع سریع

پیش‌نیازها: **Node.js ≥ 22.12**، **pnpm 10** (`corepack enable`) و **Docker** (برای PostgreSQL/Redis/MinIO).

```bash
pnpm install                 # نصب وابستگی‌های همه بسته‌ها
cp .env.example .env         # مقادیر پیش‌فرض برای اجرای محلی
pnpm infra:up                # PostgreSQL + Redis + MinIO با Docker
pnpm db:migrate              # اعمال مهاجرت‌ها
pnpm db:seed                 # داده نمونه: ۶ مدل آیفون، ۳۲ ترکیب، تنظیمات، مدیر
pnpm dev                     # API روی :4000 و فروشگاه روی :3000
```

| آدرس                               | توضیح                                                   |
| ---------------------------------- | ------------------------------------------------------- |
| <http://localhost:3000>            | فروشگاه                                                 |
| <http://localhost:3000/admin>      | پنل مدیریت                                              |
| <http://localhost:4000/api/health> | سلامت سرویس                                             |
| <http://localhost:4000/api/docs>   | مستندات Swagger                                         |
| <http://localhost:9001>            | کنسول MinIO (کاربر/رمز: `iphoneha` / `iphoneha-secret`) |

> هنگام `pnpm build` اپ وب، API باید بالا باشد تا صفحهٔ اصلی و صفحات محصول از پیش ساخته شوند؛ اگر API در دسترس نباشد، لایهٔ فروشگاه با مقادیر پیش‌فرض بالا می‌آید ولی build صفحهٔ اصلی شکست می‌خورد (عمدی، تا خطا پنهان نماند).

> اگر Docker در دسترس نیست، کافی است PostgreSQL و Redis محلی داشته باشی و `DATABASE_URL` و `REDIS_URL` را در `.env` تنظیم کنی؛ با `STORAGE_DRIVER=local` تصاویر روی دیسک ذخیره و از مسیر `/api/media` سرو می‌شوند و نیازی به MinIO نیست.

## پایگاه داده

اسکیما در `apps/api/prisma/schema.prisma` است (کاربر، نشست، محصول، ترکیب، موجودی، رزرو، سفارش، پرداخت، تخفیف، ارسال، گزارش فعالیت، درخواست خرید اقساطی، مقالهٔ مجله و…).

```bash
pnpm db:migrate        # اعمال مهاجرت‌ها (prisma migrate deploy)
pnpm db:migrate:dev    # ساخت مهاجرت جدید در حین توسعه
pnpm db:seed           # داده نمونه
pnpm db:reset          # پاک‌سازی کامل و ساخت دوباره
```

مهاجرت‌ها در `apps/api/prisma/migrations` هستند. مهاجرت `constraints_and_search` چیزهایی را اضافه می‌کند که Prisma خودش نمی‌سازد:

- افزونهٔ `pg_trgm` و ایندکس GIN روی `Product.searchText` برای جست‌وجوی فارسی،
- دنبالهٔ `order_number_seq` برای شماره سفارش (`IH100001`)،
- قیدهای `CHECK` روی موجودی (`reserved <= stock`، هیچ مقدار منفی)، تعداد و مبالغ،
- قید انحصاری‌بودن مالک نشست (کاربر یا مدیر، نه هر دو).

> هنگام ساختن مهاجرت تازه با `prisma migrate dev`، Prisma خط `DROP INDEX "Product_searchText_trgm_idx"` را پیشنهاد می‌کند (ایندکس را خودش نساخته). آن خط را همیشه از فایل مهاجرت پاک کن.

دادهٔ مرجعی که با کد عرضه می‌شود با دو اسکریپت همگام می‌شود و هر دو را `deploy.sh` در هر استقرار اجرا می‌کند:

- `pnpm --filter @iphoneha/api catalog:sync`: مدل‌ها، رنگ‌ها، حافظه‌ها و عکس‌های رسمی؛ بدون دست زدن به قیمت، موجودی و متن‌های مدیر.
- `pnpm --filter @iphoneha/api content:sync`: مقاله‌های مجله؛ هر مقاله فقط یک بار اضافه می‌شود و بعد از آن مال مدیر است (نسخهٔ ویرایش‌شده بازنویسی و مقالهٔ حذف‌شده برگردانده نمی‌شود).

## ورود مدیر

سیدر دو حساب مدیریتی می‌سازد (ورود فقط با شماره موبایل و کد یک‌بارمصرف — بدون رمز):

| شماره         | نقش           | دسترسی                                |
| ------------- | ------------- | ------------------------------------- |
| `09120000000` | `SUPER_ADMIN` | همه بخش‌ها                            |
| `09120000001` | `WAREHOUSE`   | محصولات و انبار (فقط خواندن سفارش‌ها) |

در حالت توسعه (`SMS_DRIVER=log`) کد تأیید در کنسول API چاپ می‌شود و از `GET /api/dev/otp?phone=09120000000` هم قابل خواندن است. این مسیر با `DEV_EXPOSE_OTP=false` غیرفعال می‌شود.

اگر سقف ارسال کد برای تست‌های مکرر پر شد: `pnpm otp:reset` (یا `POST /api/dev/reset-otp-limits` که خود تست‌های E2E پیش از هر ورود صدا می‌زنند؛ هر دو فقط در حالت توسعه فعال‌اند).

## مستندات API

Swagger روی <http://localhost:4000/api/docs> در دسترس است. همهٔ مسیرها پیشوند `/api` دارند و پاسخ خطاها یکنواخت است:

```json
{ "statusCode": 409, "code": "OUT_OF_STOCK", "message": "موجودی کافی نیست" }
```

خلاصهٔ مسیرها:

| گروه                     | مسیرها                                                                                                                                                                                                                                                                                                                              |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| فروشگاه                  | `GET /storefront/home` · `GET /storefront/config` · `GET /storefront/sitemap`                                                                                                                                                                                                                                                       |
| خرید اقساطی با چک و سفته | `POST /credit-requests` (فرم درخواست؛ ۵ بار در ۱۰ دقیقه برای هر بازدیدکننده، با فیلد تله برای ربات‌ها)                                                                                                                                                                                                                              |
| مجله                     | `GET /articles` · `GET /articles/:slug`                                                                                                                                                                                                                                                                                             |
| ترب و ایمالز             | `GET/POST /feeds/torob` (Torob API v3) · `GET /feeds/emalls`                                                                                                                                                                                                                                                                        |
| سبد                      | `GET/POST /cart` · `PATCH/DELETE /cart/items/:id` · `POST/DELETE /cart/coupon`                                                                                                                                                                                                                                                      |
| ارسال                    | `GET /shipping/methods`                                                                                                                                                                                                                                                                                                             |
| تسویه و سفارش            | `POST /checkout/quote` · `POST /checkout` · `POST /orders` · `GET /orders` · `GET /orders/:id` · `POST /orders/:id/cancel`                                                                                                                                                                                                          |
| پرداخت                   | `GET /payments/methods` · `GET /payments/installment-terms` · `POST /payments/create` · `POST /payments/verify` · `GET /payments/result/:orderNumber` · `POST/GET /payments/callback/:provider`                                                                                                                                     |

## تست‌ها

```bash
pnpm test              # تست‌های واحد (۲۸۳ = ۸۰ در shared + ۲۰۳ در API)
pnpm test:integration  # تست‌های یکپارچه روی API واقعی + پایگاه داده (۱۶۴)
pnpm test:e2e          # تست‌های Playwright (۸۲، شامل دسترس‌پذیری، سئو و امنیت) — نیاز به اجرای API و وب
pnpm test:all          # هر سه سطح پشت سر هم
pnpm lint              # ESLint در چهار بسته (api، web، shared، e2e)
pnpm typecheck         # tsc --noEmit در چهار بسته
pnpm format:check      # Prettier
```

وضعیت فعلی: **۲۸۳ تست واحد + ۱۶۴ تست یکپارچه + ۸۲ تست E2E = ۵۲۹ تست سبز**، lint، typecheck و Prettier بدون خطا. گردش CI در `.github/workflows/ci.yml` همین زنجیره را روی هر push اجرا می‌کند. تست‌های **امنیتی** (`apps/api/test/security.int-spec.ts`، ۱۷ مورد، و `e2e/tests/security.spec.ts`) هدرها، کوکی‌ها، CSRF، ماتریس نقش‌ها، مالکیت داده، سقف سفارش باز، نرخ‌گیری، تزریق، آپلود و callback جعلی را قفل می‌کنند؛ شرح در `docs/SECURITY.md`.

پوشش تست‌های یکپارچه: احراز هویت و نرخ‌گیری OTP، کاتالوگ و جست‌وجو، سبد خرید، تسویه، پرداخت (موفق، ناموفق، دیررس، بازگشت وجه، زرین‌پال)، هم‌زمانی، پنل مدیریت، مسیرهای فروشگاه، وب‌سرویس ترب و ایمالز، فرم درخواست خرید با چک و سفته (اعتبارسنجی، فیلد تله، درخواست تکراری، سقف ارسال، صندوق پنل و دسترسی نقش‌ها)، هشدار به فروشگاه (پیامک و ربات برای درخواست تازه و سفارش پرداخت‌شده، بدون اطلاعات مشتری، گیرنده‌های پنل، دکمهٔ آزمایش) و مجله (انتشار، نقشهٔ سایت، کاور، همگام‌سازی مقاله‌های نسخه).

تست‌های **دسترس‌پذیری** (axe-core، استاندارد WCAG 2.1 AA) دوازده صفحهٔ فروشگاه (از جمله صفحه‌های خرید قسطی و مجله)، استوری‌های بازِ صفحهٔ اصلی و هشت صفحهٔ پنل را می‌سنجند و هیچ خطایی نباید وجود داشته باشد.

تست‌های **سئو** این‌ها را قفل می‌کنند: `robots.txt`، `sitemap.xml` با تاریخ واقعی و عکس‌ها، یکتا بودن عنوان صفحه، داده‌های ساخت‌یافتهٔ `OnlineStore`/`WebSite`/`Product`/`ItemList`/`FAQPage`/`BreadcrumbList`/`BlogPosting`، تیتر و کانونیکال صفحه‌های «آیفون قسطی»، «خرید گوشی با چک» و «خرید آیفون با سفته»، وجود پاسخ پرسش‌های متداول در خود HTML، لینک‌های داخلی فوتر و `noindex` بودن صفحه‌های فیلترشده و خصوصی.

بقیهٔ تست‌های E2E شامل **استوری‌های صفحهٔ اصلی** (باز شدن، ورق خوردن با کلید و لمس، رفتن خودکار و توقف، رفتن به فرم درخواست و به ماشین‌حساب با همان سرویس، خاکستری شدن حلقهٔ دیده‌شده و حذف استوری سرویس خاموش)، **علاقه‌مندی‌ها** (ذخیره در مرورگر، نمایش در `/wishlist` و حذف)، **مدیریت محصول در پنل** (ساخت محصول → افزودن ترکیب → حذف)، **خرید کامل** (انتخاب مدل → ورود با OTP → آدرس → ارسال → پرداخت → نتیجه → مشاهده در حساب) و **Concurrent Checkout** است: دو خریدار هم‌زمان آخرین موجودی یک ترکیب را می‌خواهند و دقیقاً یکی موفق می‌شود.

اجرای E2E به صورت دستی:

```bash
pnpm --filter @iphoneha/api build && pnpm --filter @iphoneha/api start &   # API روی :4000
pnpm --filter @iphoneha/web build && pnpm --filter @iphoneha/web start &   # وب روی :3000
pnpm test:e2e
```

## توسعه و کیفیت کد

- **قالب و lint خودکار:** `pnpm install` هوک پیش از کامیت را نصب می‌کند؛ روی هر کامیت Prettier و ESLint (`--fix`) فقط روی فایل‌های stage‌شده اجرا می‌شوند و خطا کامیت را متوقف می‌کند. قواعد ESLint با اطلاعات تایپ‌اند (پرامیس بی‌`await`، `import type`، `eqeqeq`، …) — فهرست و دلیل هرکدام در [`CONTRIBUTING.md`](CONTRIBUTING.md).
- **CI:** `.github/workflows/ci.yml` روی هر push و pull request: `format:check` → `lint` → `typecheck` → تست واحد → یکپارچه → `build`، و بعد E2E روی بیلد واقعی با Postgres و Redis.
- **امنیت:** کنترل‌ها، محل هرکدام در کد، تستی که آن را قفل کرده و نتیجهٔ ممیزی در [`docs/SECURITY.md`](docs/SECURITY.md).
- **نسخه‌ها:** Node `22.12` (`.nvmrc`) و pnpm `10.28` (`packageManager`)؛ `corepack enable` کافی است.

## تصمیم‌های کلیدی

- **بدون فروش بیش از موجودی.** رزرو با یک `UPDATE` شرطی انجام می‌شود:
  `UPDATE "Inventory" SET reserved = reserved + q WHERE "variantId" = ? AND (stock - reserved) >= q RETURNING *`
  داخل یک تراکنش، با ترتیب قطعی ترکیب‌ها (جلوگیری از بن‌بست) و قید `CHECK (reserved <= stock)` در پایگاه داده به‌عنوان تور ایمنی.
- **چرخهٔ رزرو:** ثبت سفارش → رزرو (مهلت `RESERVATION_TTL_MINUTES`) → پرداخت موفق → تثبیت (`stock -= q`, `sold += q`)؛ شکست یا انقضا → آزادسازی توسط کار زمان‌بندی‌شدهٔ BullMQ.
- **پرداخت idempotent.** هر تراکنش با `Idempotency-Key` و `@@unique([provider, providerRef])` ثبت می‌شود؛ بازگشت دوباره از درگاه سفارش تکراری یا پرداخت دوباره نمی‌سازد. پرداخت موفقی که پس از انقضا برسد، دوباره رزرو می‌شود و اگر موجودی نبود، خودکار به بازگشت وجه می‌رود.
- **همهٔ مبالغ عدد صحیح به تومان** هستند (`BigInt` در پایگاه داده) تا خطای اعشار پیش نیاید.
- **اسنپ‌شات سفارش:** نام، قیمت، تخفیف، SKU و زمان ارسال هر قلم در زمان ثبت سفارش ذخیره می‌شود تا تغییر بعدی محصول فاکتور گذشته را عوض نکند.
- **امنیت:** نشست با توکن ۳۲ بایتی (ذخیرهٔ SHA-256)، CSRF دوکوکی‌ای، اعتبارسنجی Zod روی همهٔ ورودی‌ها، نرخ‌گیر Redis، `helmet`، RBAC با مجوزهای ریز و ثبت گزارش فعالیت با مقدار قبل/بعد.
- **دسترس‌پذیری:** رنگ‌های خاکستری نسبت به فایل طراحی کمی تیره‌تر شده‌اند تا همهٔ اندازه‌های متن نسبت کنتراست ۴.۵:۱ (WCAG AA) را روی سفید و سطوح روشن رد کنند؛ این موضوع با axe-core تست می‌شود.
- **رابط کاربری:** کارت محصول با انتخاب رنگ، نشان تخفیف، قلب علاقه‌مندی و دکمهٔ تمام‌عرض؛ نوار خرید چسبان در موبایل؛ جدول «مقایسه مدل‌ها» که ردیف‌هایش از `specs` واقعی همان محصول‌ها ساخته می‌شود؛ بخش «امتیاز خریداران» بر پایهٔ `ratingAvg`/`ratingCount` واقعی؛ فیلترهای جمع‌شونده با شمارنده و «پاک کردن همه»؛ اسکلت بارگذاری هنگام تغییر فیلتر.
- **سئو:** مسیر `/iphone/<slug>`؛ JSON-LD شامل `OnlineStore`، `WebSite` با `SearchAction`، `Product` (قیمت، موجودی، امتیاز، گارانتی، شرایط ارسال و بازگشت کالا)، `BreadcrumbList`، `ItemList`، `FAQPage` و `BlogPosting`؛ `sitemap.xml` با `lastmod` واقعی و عکس‌ها؛ `robots.txt` با بستن مسیرهای خصوصی؛ صفحه‌های فیلترشدهٔ فروشگاه `noindex, follow` با کانونیکال به `/shop`؛ تصویر اشتراک‌گذاری اختصاصی و آیکن‌های سایت.
- **صفحه‌های کلمهٔ کلیدی:** `/installments` («آیفون قسطی»، «خرید گوشی قسطی»)، `/installments/cheque` («خرید گوشی با چک») و `/installments/safte` («خرید آیفون با سفته»)، هر کدام با یک H1، جدول قیمت اقساطی همهٔ مدل‌ها، مراحل، مدارک، فرم درخواست و پرسش‌های متداول. همهٔ ارقام (پیش‌پرداخت، تعداد اقساط، کارمزد، سقف، ضامن، مدارک) از پنل ← تنظیمات ← «چک و سفته» خوانده می‌شود و تا مدیر پرشان نکرده، متن به‌جای عدد می‌گوید چطور تعیین می‌شوند. مجلهٔ `/mag` با مقاله‌های Markdown (ویرایشگر پنل با پیش‌نمایش و چک‌لیست سئو) به همین صفحه‌ها لینک می‌دهد. پرسش‌های متداول با `<details>` ساخته شده‌اند تا پاسخ‌ها در خود HTML باشند.
- **استوری‌های خرید قسطی:** ردیف حلقه‌ها بالای صفحهٔ اصلی، مثل استوری اینستاگرام: «آیفون قسطی» (با قسط ماهانهٔ نمونه از همان ماشین‌حساب)، چک صیادی، سفته، هر سرویس اعتباری که همین حالا در تسویه فعال است (اسنپ‌پی، تارا، دیجی‌پی، باجت، ازکی‌وام، نسیبا؛ با بنر خودش اگر دارد) و «راهنما» از تازه‌ترین مقاله‌های مجله. همه از تنظیمات زنده ساخته می‌شوند، پس سرویسی که خاموش یا هنوز ماک است استوری ندارد. نمایشگر در موبایل تمام‌صفحه و در دسکتاپ کارت ۹:۱۶ است: لمس یک‌سوم راست قبلی و بقیه بعدی، کشیدن به چپ و راست استوری بعد و قبل، کشیدن به پایین یا Escape بستن، نگه‌داشتن یا دکمهٔ توقف مکث؛ هر اسلاید ۶ ثانیه و برای کسی که «حرکت کمتر» را در سیستم روشن کرده بدون زمان‌سنج. حلقهٔ دیده‌شده در همان مرورگر خاکستری می‌شود و کد نمایشگر فقط وقتی کسی استوری را باز کند بارگذاری می‌شود.
- **استقرار:** پوشهٔ [`deploy/`](deploy/README.md) شامل کامپوز دیتابیس و ردیس، یونیت‌های systemd، پروکسی nginx و Apache برای cPanel، اسکریپت استقرار و پشتیبان‌گیری، و راهنمای گام‌به‌گام سرور.

جزئیات بیشتر در [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## اجرا با Docker

```bash
cp .env.example .env
docker compose up -d                  # فقط زیرساخت
docker compose --profile app up -d    # به‌علاوه API و وب (build از Dockerfileها)
```

> `Dockerfile`های API و وب نوشته شده‌اند اما در محیطی که پروژه ساخته شد Docker daemon در دسترس نبود، پس ساخت ایمیج‌ها آزمایش نشده است؛ اولین `docker compose --profile app build` را با حوصله اجرا کن.

سرویس API هنگام بالا آمدن `prisma migrate deploy` را اجرا می‌کند؛ برای داده نمونه یک بار `pnpm db:seed` را با `DATABASE_URL` همان کانتینر اجرا کن.

## کارهای باقی‌مانده برای محیط واقعی

این موارد عمداً به کلید/قرارداد واقعی وابسته‌اند و با آداپتور ماک پیاده شده‌اند تا بدون آن‌ها هم کل جریان کار کند:

- کلید درگاه پرداخت آنلاین (زرین‌پال، با `deploy/go-live.sh`) و کلیدهای سرویس‌های اقساطی. اسنپ‌پی، تارا، دیجی‌پی، باجت و ازکی‌وام کلاینت واقعی دارند و با `deploy/installments.sh` روی سرور وصل می‌شوند: اول با کلید تست (فقط کارکنان می‌بینند)، بعد با کلید اصلی. راهنمای کامل در `deploy/README.md` ← «خرید قسطی آنلاین». نسیبا API عمومی برای فروشگاه‌ها منتشر نکرده و مستندش با قرارداد پذیرندگی می‌آید؛ تا آن موقع فقط آداپتور ماک دارد و در production نمایش داده نمی‌شود.
- پنل پیامک واقعی (`SMS_DRIVER`) برای ارسال کد ورود و اطلاع‌رسانی سفارش.
- شرایط خرید با چک و سفته (پیش‌پرداخت، تعداد اقساط، کارمزد و…) در پنل ← تنظیمات ← «چک و سفته»؛ تا پر نشوند، محاسبه‌گر و ستون‌های قسط ماهانه نمایش داده نمی‌شوند.
- هشدار درخواست قسطی تازه و سفارش پرداخت‌شده: داخل پنل خودکار است؛ پیامک و ربات تلگرام یا بله با `deploy/alerts.sh` روی سرور وصل می‌شوند و گیرنده‌ها در پنل ← تنظیمات ← «هشدارها» تعیین می‌شوند.
